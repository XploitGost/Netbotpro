# Deployment Overview

NetBotPro v0.2.0 supports local demos, desktop use, controlled Remote Sensor
deployments, and read-only Agent/Fleet monitoring. Deploy only on systems,
servers, and networks you own, administer, or have explicit permission to
monitor.

## Local Demo Deployment

Install dependencies, start the backend, seed realistic Agent data, and
optionally start the frontend:

```powershell
python -m pip install -r requirements-dev.txt
cd frontend
npm ci
cd ..
powershell -ExecutionPolicy Bypass -File .\scripts\dev\start-demo.ps1 -StartFrontend
```

Open `http://127.0.0.1:5173/?page=agents`. The launcher stores the local token
in `.runtime/demo-local-token.txt` and prints only the file path.

## Desktop And Electron Usage

The Electron desktop shell runs the local backend and frontend as a local-first
application. Development launch:

```powershell
cd desktop/electron
npm ci
npm run dev
```

Release artifacts are generated by `packaging/windows/build.ps1` or the
tag-driven `Release Desktop` GitHub Actions workflow.

## Remote Sensor Over VPN Or Private Network

Remote Sensor Mode runs the FastAPI capture backend on an authorized server.
Keep it behind a VPN, private subnet, SSH tunnel, or TLS reverse proxy. Restrict
operator access with firewall rules and `NETBOT_REMOTE_IP_ALLOWLIST`.

Use metadata capture by default. Full and Forensic capture require explicit
authorization, Safe Use acceptance, audit logging, and appropriate retention.
See [Remote Sensor Mode](REMOTE_SENSOR.md) and [Capture Modes](CAPTURE_MODES.md).

## Agent And Fleet Central Deployment

Agent Mode sends redacted summary telemetry to a central backend. It does not
send raw packets, raw payloads, PCAP files, files, or command output.

Recommended central deployment:

- Put the central backend behind a VPN/private network or TLS reverse proxy.
- Configure a strong `NETBOT_AGENT_TOKEN`.
- Configure a separate strong `NETBOT_LOCAL_TOKEN` for operator dashboard
  access.
- Back up `.runtime/logs/agents.db`.
- Set `NETBOT_AGENT_OFFLINE_AFTER_SECONDS` and
  `NETBOT_AGENT_HISTORY_RETENTION_DAYS` for the deployment.
- Schedule `scripts/dev/cleanup-agent-history.ps1` with a dry-run review first.

## Linux Systemd Deployment

Use `packaging/systemd/netbotpro-sensor.service` as a reviewed template. Set:

- `WorkingDirectory` to the deployed repository/runtime.
- `EnvironmentFile` to a root-readable configuration file.
- `ExecStart` to the intended Python environment.
- capture capabilities or root privileges only when live capture requires
  them.

Then validate:

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now netbotpro-sensor.service
sudo systemctl status netbotpro-sensor.service
```

## Windows Script Or Service Deployment

Windows development and initial deployment scripts live in `scripts/dev/`:

- `start-sensor.ps1`, `status-sensor.ps1`, `stop-sensor.ps1`
- `start-agent.ps1`, `status-agent.ps1`, `stop-agent.ps1`
- `start-demo.ps1`

For long-lived services, use a reviewed Windows service wrapper or Scheduled
Task with restart-on-failure. Keep PID and logs under `.runtime`.

## Security Checklist

- Use the tool only on authorized systems and networks.
- Keep Remote Sensor and central Agent APIs off the public internet.
- Use VPN/private routing or a TLS reverse proxy.
- Use strong, unique tokens and rotate them when exposure is suspected.
- Never commit tokens or environment files containing secrets.
- Keep payload capture disabled unless explicitly authorized.
- Verify redaction in UI, logs, reports, and exports.
- Review audit logs before and after Full or Forensic capture.

## Firewall And VPN Notes

Allow only required operator and Agent source networks. Prefer inbound firewall
allowlists over broad port exposure. A token is not a substitute for VPN,
private routing, TLS, or firewall policy.

## Token Handling

Token files under `.runtime` must be readable only by the intended operator or
service account. Start/status/demo scripts print token file paths, not raw
tokens. Do not paste tokens into tickets, chat, screenshots, or source control.

## Logs And Runtime Paths

Common paths:

```text
.runtime/logs/
.runtime/logs/agents.db
.runtime/logs/audit.jsonl
.runtime/logs/sensor-backend.log
.runtime/logs/sensor-backend.err.log
.runtime/logs/agent-runner.log
.runtime/logs/agent-runner.err.log
.runtime/demo-local-token.txt
```

Apply retention, access control, and backup policy appropriate to the data.

## Troubleshooting

- Backend will not start: run `python -m pip check` and inspect the relevant
  `.runtime/logs/*.err.log`.
- Frontend will not start: run `cd frontend`, `npm ci`, and `npm run build`.
- No capture interfaces: install Npcap/libpcap and verify capture permissions.
- Agent remains offline: confirm central API reachability, Agent token, and
  `NETBOT_AGENT_OFFLINE_AFTER_SECONDS`.
- Remote dashboard is rejected: confirm remote access opt-in, token, origin,
  firewall, and IP allowlist.
- Release artifact missing: inspect the `Release Desktop` workflow and
  SHA256SUMS artifact.
